# Canonical owner intake v2 — source preparation, runtime OFF

This change implements an isolated canonical protocol for the existing owner gateway, Make scenario `6176241` and KK Agent Apps Script project. It does not deploy, migrate a live database, save Apps Script, edit Make, activate a transport, replay a row, or send a provider request. Source tests and synthetic SQL ACKs are not provider delivery evidence.

## Implemented flow

1. A dedicated same-consumer bearer credential authenticates every canonical gateway request. The existing transport gate, canonical gate, producer gate, fixed project binding and OAuth binding must all be configured. Missing/disabled configuration rejects before network. Credentials are read only from runtime/provider secret stores; the compiler contains connection IDs, never their credentials.
2. The authenticated same-project OIDC Edge allowlist calls one narrowly scoped native canonical RPC. A locked, trusted cutover row supplies immutable activation time, policy, environment and consumer. No cutover row is seeded by this staged migration. A unique 900-second slot can produce one poll context during its first 120 seconds.
3. Fixed Apps Script Execution API calls use `devMode:false` and only `runCanonicalOwnerLedgerPoll`, `runCanonicalOwnerLedgerClaim`, `finalizeCanonicalOwnerLedgerAck`, or `finalizeCanonicalOwnerLedgerRejection`. OAuth refresh uses the fixed Google token endpoint with no retry; neither access tokens nor provider secrets appear in responses. The separate private Core reader is not used.
4. GAS verifies a purpose-separated HMAC and exact local cutover/project/environment binding. Poll/claim also honor `CORE_V1_TRANSPORT_ENABLED`. Under the existing ScriptLock it reuses Core candidate selection, quiet hours, message renderer, full-row CAS, dedup witnesses, claim and exact projection/readback. Normal Telegram candidates in the timed Core runner are suppressed before claim when canonical mode is selected; the LINE path is unchanged.
5. A bounded, complete poll snapshot yields opaque durable tickets. Invalid normal rows are isolated per candidate and return explicit `held` debt; they remain unchanged and unrelated valid rows continue. The complete original snapshot and every identity/dedup witness remain present. Make iterates `{ticket}` objects and admits each just in time. Native `begin` consumes the ticket and creates a unique identity/dedup fence **before** GAS can claim. Unknown GAS outcomes remain `CLAIMING`/Sheet `SENDING`; there is no reset, expiry renewal, automatic retry or resend transition.
6. Enqueue atomically verifies the original row, exact claimed row, trusted context and original descriptor, then records the immutable binding and descriptor. Only that persisted descriptor is signed. The response includes `envelope_json`, so Make can preserve exact JSON escaping.
7. `canonical-prepare` reserves one provider attempt. The gateway checks the original expiry with a 15-second margin before and after reservation; the Make provider filter checks the same deadline immediately before dispatch. `canonical-ack` commits receipt-bound native `SENT` and reads it back. `canonical-project` separately projects/readbacks the Sheet ACK. A projection failure can be repaired after descriptor expiry using the original signed envelope and durable `SENT`, without reservation or provider send.

## Clocks and immutable identity

Business `Created At` stays exactly in binding index 5, including valid original offset strings. It must be at/after the trusted activation cutoff and no later than the current observation. There is no 120-second or current-slot age cap on the business row. A row held during Bangkok 23:00–07:00 remains QUEUED with the same identity and can qualify during a later fresh poll. Only the established P0 cancellation/postponement/date/venue rules bypass quiet hours; generic material updates cannot.

Poll observation and exact claim each remain fresh within 120 seconds with at most 15 seconds of future skew. The original signed descriptor lasts at most 120 seconds. An attempted descriptor is never recreated or extended.

The v2 binding has the established first 13 positions with version `kk-owner-ledger-binding-v2`, followed by the serialized trusted context and exact Sheet claim ID. Normal selection follows the existing governed Core rules and excludes controlled-UAT markers. The current Core/policy has no exhaustive normal change-type enum; this implementation does not invent one from fixtures.

## Additive storage and security

`supabase/staging/kk-owner-ledger-canonical-v2.sql` adds five RLS-enabled canonical tables and a fixed-search-path RPC. The fifth table retains one row per attempt, its original descriptor, claim, reservation, receipt and outcome. No v1 UAT table, validator, trigger or RPC body is changed. Existing UAT grants/claims/fixtures remain untouched.

Public, anon, authenticated and service-role callers have no direct canonical table privileges. Only service_role may execute the allowlisted operation RPC; its `SECURITY DEFINER` body validates and locks the trusted configuration within the same transaction. Unique slot, ticket, raw identity, dedup and receipt constraints fence races. The activation epoch and other cutover bindings cannot be rewritten; only its enable flag may change through a separately authorized owner operation. Explicit JSON type/null checks and UTF16 message bounds match the gateway/wire contract.

An attempted state is a reconciliation hold unless exact native receipt evidence reaches durable SENT or a strictly bound, definitive original Telegram rejection is persisted. Rejection stays fenced until the exact Sheet `RETRY_WAIT` or `FAILED` row is signed, read back and confirmed natively. Only a due `RETRY_WAIT` source below the Core attempt cap can receive a new ticket in a later 900-second poll; its original Created At, dedup and business fields stay unchanged. A new claim and original 120-second descriptor belong to the new attempt. Old rows and consumed UAT fixtures cannot be re-aged or admitted through canonical v2.

The v2 poll result carries `rows`, valid `candidates`, and `held`. Each held entry contains only a bounded data-row index, an identity SHA256 witness, and a fixed allowlisted reason code. For string identities the hash preimage remains the exact JSON-encoded original string. For malformed non-string identities it is the fixed UTF8 text `KK_OWNER_CANONICAL_HELD_NONSTRING_V2`, one LF byte, and the JSON type name (`number`, `boolean`, `null`, `array`, or `object`). No layer reserializes the arbitrary non-string value for hashing. Distinct malformed IDs of the same type intentionally share a hash; held entries are unique by row index, and the full original snapshot retains their actual values and dedup witnesses. Metadata never contains payloads, arbitrary exception messages or raw malformed identities. At most 128 entries and 32 KiB of metadata are accepted. The gateway performs a second per-candidate admission check; rejected candidates become explicit held entries rather than poisoning the batch. The native tickets operation requires all four fields `{context,rows,candidates,held}` and atomically stores held metadata with poll issuance. Authenticated `canonical-poll-readback` (`version:v2`, `poll_id`) and native `poll-readback` expose this retained operator evidence. Held sources receive no ticket or Sheet write; a conflicting witness still holds the otherwise-valid source.

Native claimed `Last Attempt At` must be a nonempty JSON string in the canonical UTC millisecond format, round-trip to a finite timestamp, and satisfy freshness. Missing/null/numeric/object/array/infinite/malformed values cannot leave CLAIMING or obtain a descriptor/reservation. The database refreshes its clock after blocking configuration, poll, ticket and delivery locks before freshness/TTL checks and receipt timestamp writes. No caller-supplied clock or extended descriptor replaces that proof. The immutable native cutover sets `max_attempts` from 1 to 4; the signed poll context binds this exact ceiling to GAS Core's effective configured ceiling before any Sheet claim. Multi-session contention still requires separate runtime verification.

## Definitive rejection and retry boundary

The negative route accepts only a configured, independently reviewed original structured Telegram response capture for native module 8 on scenario 6176241 and connection 10356915. Its profile digest covers the fixed scenario/module/connection, observed connector schema hash, exact provider route hash and all eleven field mappings; the builder, gateway configuration and native cutover must match that reviewed digest. The gateway compares the exact attempt, receipt, source and native descriptor digest with durable readback. Admit and Prepare expose the stored native digest so the callback need not recompute JSONB serialization. Both gateway and native RPC require `ok:false`, a numeric original HTTP status matching `error_code`, no acceptance/result/message identifier, and a sane `retry_after`. A generic Make `RateLimitError`, free text containing `429`, absent ACK, timeout, 5xx, or 408/409/425 is unknown and remains fenced. The current public Make execution logs do not expose the original Telegram response body; no live profile has been verified or bound by this source change.

For a proven 429, native persistence precedes GAS projection. The exact full `RETRY_WAIT` row, including attempt count, claim note, HTTP status and `Next Retry At`, must be signed/read back by GAS and confirmed in native storage. A definitive other 4xx is projected `FAILED`; a 429 at the effective maximum is also terminal. Attempt 1/2/3 Core minimum waits are 5/10/20 minutes, with Telegram `retry_after` as a lower bound. The existing 900-second poll cadence supplies the next opportunity after the due instant; there is no Make sleep, automatic resume, replacement scheduler or retry of an old envelope. A failed projection is repair only. Manual or mismatched Sheet retry rows receive bounded hash-only held debt and no ticket while unrelated valid sources continue.

## Guarded Make preparation

`server/make-owner-canonical-builder.js` is an offline compiler for the existing scenario. It requires a fresh inactive snapshot, zero incomplete executions, matching `expectedLastEdit`, the verified existing Telegram connection `10356915`, a separately verified HTTP connection scoped to the exact gateway URL, and actual new module IDs returned by a separately approved Make save. Unknown error routes are refused. A negative route may be carried only from a fresh OFF snapshot with an exact separately reviewed module-8 error route, assigned callback modules, structured response field mappings and matching review/schema/route digests. No Make error body field is assumed by source.

It produces the desired flat poll → iterator → admit → existing 6 prepare → existing 8 Telegram → existing 9 durable ACK → HTTP projection graph, with active false and provider 8 disabled. Old on-demand modules 5/10 and their references are removed. The Telegram mapper uses the native numeric `message_id`, quoted as a JSON string for ACK, and plaintext rendering. The emitted provider filter requires `send_allowed`, a receipt and original expiry > now + 15 seconds.

HTTP v4 and iterator v1 fields were checked against current connected module schemas. The compiler emits native indefinite/900 schedule intent and empty input/output intent; it does not invent unsupported scheduling/interface patch operation names. Exact tool validation of that complete desired graph, schedule, interfaces, filters and readback remains a release gate. Sequential processing, DLQ off, zero incomplete executions and no Make retry/Break/Resume/sleep routes are required. An error callback may persist a proven rejection and project it, then Commit; no incomplete execution may resume at provider 8 after an unknown outcome.

## Source verification and remaining gates

An unused retry admission is distinct from an attempted delivery. A later eligible poll may replace the pointer to a NEW ticket only after its original poll expires, with exact source/dedup/projected-row and cutover match, and no attempt history for that ticket. The old ticket is retained; consumed, CLAIMING, QUEUED, RESERVED and SENT attempts are never reopened. Duplicate candidate IDs fail before ticket inserts. The delivery lock and a fresh native clock check protect the transition to CLAIMING after any lock wait.

The reviewed negative Make graph uses the documented flat error-handler parent on module 8, HTTP rejection persistence, the following HTTP projection and a following `builtin:Commit` terminal. Callback requests use the existing gateway-scoped authentication binding. Numeric attempt/HTTP values and the structured Telegram response remain JSON numbers/objects. Raw Sheet source identity is JSON-encoded separately from the encoded transport notification identity so quotes and backslashes cannot corrupt the body. These are offline compiler/source guarantees; the live connector's original negative-response schema is still unverified and no synthetic profile authorizes a runtime capture binding. A negative callback arriving after the original 120-second envelope expiry remains held; only already-durable positive/negative projection can repair after expiry without sending again.
