- A fresh prepared exact attempt/receipt enters the Make action. First request calls only the fixed authenticated gateway to acquire a durable one-use native dispatch grant. Second request calls only fixed Telegram sendMessage with the gateway-returned rendered owner chat/text. Re-executing the full action cannot acquire another grant.
- Immutable custom provider binding identifies the actual new app/module/secure connection/public bot and reviewed manifest. The opaque native connection10356915 is not assumed compatible or copied. Missing binding remains OFF/unavailable. Existing native mode and UAT remain separate.
- Gateway bearer is request-specific to the gateway and never a global Base Authorization. Bot token is stored only in the Make connection and used only at the fixed Telegram endpoint. Connection fields and token URL/request/response logs are sanitized. Source contains templates, no secret values.
- Full original body survives capture, including contradictory acceptance fields. Strict bounded parsing/classification handles accepted IDs, proven refusals and unknown outcomes separately. Source/dedup/original CreatedAt stay immutable; each permitted attempt has its own native history/receipt/dispatch.
- Existing native rejection-before-Sheet, signed exact GAS projection, confirmed due retry, cap/quiet-hour/TTL guards and native ACK-before-Sheet remain authoritative. No Break/Resume/sleep/platform rate-limit scheduler is introduced.
- Native dispatch CAS proves one grant per attempt. It does not certify Make's internal per-request network retry granularity; that must be validated before activation. Unknown outcomes cannot be reset to acquire a new grant.
