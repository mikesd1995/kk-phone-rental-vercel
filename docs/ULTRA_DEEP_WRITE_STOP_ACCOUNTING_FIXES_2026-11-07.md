# Ultra Deep Direct write-stop and accounting fixes — 2026-11-07

Local source scope: audited F03/F04/F05 on base `d4bd11f6ff78f67f41b79a26448d036007737701`.

- Direct requires a complete, exact update receipt before starting CREATE. The first failed, missing, malformed or ambiguous CREATE receipt stops subsequent protected writes and leaves acceptance `INCOMPLETE`.
- `production_writes` remains the count of accepted admin writes, including accepted writes whose readback failed. `verified_writes` counts exact readbacks; `attempted_writes` counts admin request dispatches; `unknown_write_outcomes` counts dispatched requests without an attributable accepted outcome. These counters describe governed operations, not physical database rows. A missing receipt cannot establish zero writes: any attributable count is retained and an unaccounted attempted operation stays unknown.
- The V2 update writer preserves earlier accepted/verified counts on transport or readback failure. The governed CREATE executor attaches a bounded `write_footprint` to errors after dispatch or acceptance, including `PROMOTION_READBACK_FAILED`. Direct copies only footprint counters and fixed failure codes, without raw provider error bodies or messages. A successful HTTP response also needs an explicit `ok: true` admin receipt.
- The authenticated `ultraDeepDirectRun` handler now uses the same `YYYY-MM` shape check as Direct and the native route. Calendar semantics and write authority are unchanged.

Independent-review amendment R1-R3: CREATE acceptance requires the actual Executor and Promotion success schema/status, an empty blocker list, a nonblank verified event identity and the existing publish/pricing verification fields. Any identity supplied in the existing admin result/direct/data shape must agree; an admin result without an identity remains compatible when exact verification supplies it. Null/string/frozen rejections are normalized to safe errors before footprint attachment, preserving an accepted CREATE without copying opaque thrown values. Footprint normalization classifies the entire attempted-minus-accepted gap as unknown, including contradictory returned or thrown metadata.

Validation: the new behavior suite now contains 54 tests; it and the existing Direct/workflow/V2/executor suites pass together (113 tests). Original RED logs cover the initial defects (14 expected failures), missing boundary receipts/earlier-write exceptions (3), and malformed success evidence (2). Amendment RED reproduced 31 expected R1-R3 failures, followed by 113/113 GREEN through the credential-scrubbed, senders-OFF, external-network-denied test wrapper. Full regression and scoped independent re-review remain separate gates.

Test boundary: normal and failure scenarios run real Direct, runtime discovery, verifier, commercial preparation, V2 plan construction, writer, executor and acceptance with controlled external search/page/admin/snapshot transports. Direct's adapter plan is a controlled fixture because the current verifier does not retain the demand fields needed to naturally admit new CREATE candidates. Separate fault-contract tests inject malformed writer returns, and a real-adapter reference test checks terminal/mutation shape. These tests prove orchestration and accounting behavior, not end-to-end discovery admission or live runtime acceptance.

No production write, merge, deployment, health call, runner activation, provider send, replay, policy or credential change was performed for this source fix.
