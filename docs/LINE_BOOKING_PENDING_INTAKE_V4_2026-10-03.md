# LINE pending booking intake v4 — current-schema fresh-port — 2026-10-03

## Why v4
PR #391 was closed without merge and is 154 commits behind current main. Its core safety model remains useful, but its Booking write contract is stale: current Apps Script 9.5.13 owns canonical `booking_id` directly in column A and writes A:T, while #391 expected a formula-generated ID after a B:T write.

## Current implementation
This fresh-port keeps the capability dormant and updates it to the current booking schema.

- Node `line-booking-intake` now emits `action=createLineBookingPending`, never the legacy `createBooking` action.
- Apps Script adds a separate `createLineBookingPending` route.
- One document lock covers deterministic request claim, canonical ID allocation, row allocation, A:T write, flush, readback and claim finalization.
- The writer hard-codes `pending / unpaid / LINE`, amount received 0, and blank phone/lens asset IDs.
- The canonical `booking_id` is generated by the same current-schema allocator used by the backend and written to column A.
- A PENDING claim records request ID, row, canonical booking ID and customer/event identity before the Booking mutation.
- Redelivery of an OK claim replays the same canonical booking.
- Redelivery of a PENDING claim may self-reconcile only if the exact claimed A:T row matches booking ID, event, customer identity, LINE source, pending/unpaid state, zero amount, blank assets and the request marker. Reconciliation never allocates or writes a replacement Booking row.
- Any mismatch remains fail-closed.

## Activation boundary
The public LINE webhook is intentionally still reply-only. It does not import the intake module and does not call either booking action. Production/business booking writes remain disabled from LINE.

Repository Apps Script is not production authority by itself. Current deployment safety rules still require authenticated Apps Script authority/source-equivalence acceptance before any production script replacement or LINE write activation.

## Supersedes
This is the current-main successor to closed PR #391. It does not reuse #391's stale B:T/formula-column-A write contract.

## CI guard
Because the repository-wide Admin Regression workflow is currently manual-only, this change adds a path-scoped LINE Pending Intake Acceptance workflow. It executes the same syntax, full regression, invariant, code benchmark and fail-closed HF safety steps whenever this critical path changes. Vercel Preview quota is not used as a code-quality signal for this writer.
