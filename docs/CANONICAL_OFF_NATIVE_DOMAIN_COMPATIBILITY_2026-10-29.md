# Canonical OFF compiler compatibility with native omitted domains

This change is limited to the pure `prepareAdapterOff` source compiler. It adds no runner, provider path, credential, endpoint, activation, gateway/GAS/Edge deployment or production operation.

The actual Make6176241 readback after seven inert helper additions contains HTTP26/27/28/29/30, Iterator31 and Commit25 with literal `config:{}`. Existing SDK11/12/13 retain only their connection parameters and omit mapper. All ten canonical modules remain disabled orphans; native8 and the original five-module legacy path remain unchanged. The prior compiler required explicit parameters/mapper objects for every module and rejected this genuine native serialization before it could prepare the complete desired configuration.

Writing empty mapper objects first is not a valid repair assumption. HTTP and SDK schemas require their real fields; Commit is a directive and may be invalid outside its final error arm. Make can also omit empty domains again. No readback may be fabricated by inserting `{}` merely to satisfy a source precondition.

The compiler now accepts only genuinely absent own parameters/mapper domains while keeping config itself a plain object. If a domain is present, undefined, null, arrays, strings, booleans, numbers and nonplain objects remain rejected. SDK connection parameters remain mandatory own objects and must match the independently supplied adapter binding; only SDK mapper may be absent. HTTP parameters may be absent for an inert native module, but present noAuth, wrong connections, TLS/proxy or unknown parameter keys still fail closed. No input property is inserted or mutated.

The desired output remains fully configured and uses the same internal DAG, JSON-safe envelope mappings, fixed gateway/secure connections, positive and rejection projection paths, disabled provider/roles and orphan poll root. Existing exact15-cardinality, actual-ID/type/version, freshness/CAS, legacy topology/config preservation, settings/interface/on-demand, adapter digest and original TTL/freshness checks are unchanged. The compile result remains source-only OFF staging, not permission to execute, cut over, send or replay.

Regression tests reproduce actual omitted-domain shapes without importing live IDs as installer defaults. They assert immutable missing-domain readback, complete intended output and unchanged legacy/trigger/interface/settings. Negative cases distinguish absence from present malformed domains, require SDK connection parameters and retain HTTP auth/TLS/proxy conflict rejection. TDD red and green evidence and actual unchanged snapshot/candidate hashes are recorded in the local continuation packet `outputs/kk-canonical-off-wiring-20261029` outside the repository.

This compatibility fix requires independent review and the repository engineering gate. Local tests or a compiled OFF graph do not prove a Make save, actual provider response handling, native ACK, Sheet projection, operational GAS or natural Scanner/Verifier runtime. A gateway deployment is not needed merely to use this local pure compiler. The old future-cutover builder remains outside this OFF staging change.
