## 2026-10-15 follow-up — fail-closed schema/diagnostic hardening (Draft #739 only)

**Root-cause independently identified from exact Draft source**: `scripts/core-private-cutover-preflight.cjs:hasHeader()` previously scanned **all rows** for a matching header cell, meaning a booking/customer data row containing `booking_id` could make an incorrect source schema appear ready. Separately, the strict private `server/admin-sheet-fallback.js:readSpecPrivate()` reused a parser that searches later rows for headers; this could bypass the intended first-row schema check if the preflight were omitted or state drifted. Error classification also echoed arbitrary upstream codes starting `CORE_PRIVATE_` or `CRM_PRIVATE_`, a potential sensitive-data echo in diagnostic results.

**Changes staged on existing Draft [#739](https://github.com/mikesd1995/kk-phone-rental-vercel/pull/739), not on main**:
1. `scripts/core-private-cutover-preflight.cjs` now checks the required header **only in row 0** of an A1/A4 bounded range. It fails closed if `booking_id` or another required header is present only in data rows. For diagnostic errors, classification now uses an explicit allowlist of known opaque `CORE_PRIVATE_`/`CRM_` failure codes, returning `CORE_PRIVATE_PROBE_FAILED` for arbitrary prefix lookalikes that may contain user identifiers/tokens. Commits `88f8ecc865ea5671f9ce0ba6902f349eb245fcb1` and `c514c6f7bd6fd361ab7d483db7b68416b508f75e`.

Existing flexible header discovery remains intact in legacy/non-cutover paths to avoid breaking today's Production until the controlled migration. Commit `24a704963213729464b4e9ba650cb90b404c5ffd`.
3. `tests/core-private-cutover-preflight.test.js`: two new tests (direct header detection and 13-dataset private probe rejecting a second-row fake booking header) plus error-code sensitive-suffix rejection assertions. Test commits `fa9b9607a94b144a4d5a3d6a595c24462bf75310`, `494270d81e808597442801749db4df33b325d898`, `de155d8e483e9bdf1579be01954fd2261426d1ff`.
